# 技巧｜10 个 Token 节省技巧

作者：云舒，TRAE 产品运营

我们在上一篇已经带大家认识了 Token 和上下文窗口，那在 TRAE 中究竟应该如何节省 Token 呢？本文将从 AI Coding 的六问心法出发，到 10 个具体场景的小技巧，手把手教你如何用 TRAE 更省钱！

### Token 花销的构成

一次对话的成本 = 输入 Token（你发给 AI 的所有内容）+ 输出 Token（AI 回答的内容）

### AI Coding 的六问心法

1. 我现在正在做什么？
2. 我希望 AI 帮我做什么？
3. 我需要提供哪些背景信息？
4. 我希望 AI 以什么格式输出？
5. 这个任务有多复杂？
6. 我是否可以利用已有知识？

### 10 个技巧

**技巧一：适时新开对话，保持任务焦点**
- 每个对话专注于一个独立任务
- 任务完成后及时开启新对话
- 避免上下文污染和 Token 浪费

**技巧二：精准限定范围，减少噪声输入**
- 明确指定要修改的文件和代码范围
- 使用 @ 符号引用特定文件
- 避免让 AI 扫描整个项目

**技巧三：优化输入内容，有效沟通**
- 使用结构化、清晰的 Prompt
- 明确角色和输出格式
- 利用 TRAE 的"优化输入内容"功能

**技巧四：批量处理，降低交互频率**
- 将多个相关子任务打包成复合指令
- 并行执行搜索和相似操作
- 减少"一问一答"的碎片化交互

**技巧五：主动引导输出，给出辅助指令**
- 明确要求"不要解释"或"直接给出代码"
- 指定输出格式（JSON、Markdown 表格等）
- 主动打断无效输出

**技巧六：先计划再行动，用 Plan/Spec 驾驭复杂任务**
- 使用 /plan 命令生成执行计划
- 使用 /spec 命令生成需求大纲、任务清单和验收标准
- 确认后再执行，避免返工

**技巧七：善用上下文压缩，为对话"减负"**
- 在任务阶段完成时手动压缩
- AI 响应质量下降时触发压缩
- 对话主题转移前进行压缩

**技巧八：固化长期知识，构建专属"工具库"**
- 使用 Rules 固化个人习惯和项目约束
- 使用 Skills 模板化高频任务流
- 打开 Memory 保存偏好

**技巧九：配置 Ignore 文件，从源头切断噪声**
- 排除 dist/、build/、日志文件等
- 避免误操作将大文件带入上下文

**技巧十：根据任务选择模型，利用模型优势**
- 简单任务用性价比模型
- 复杂任务用高性能模型
- 避免在同一任务中频繁切换模型

### TRAE 在上下文管理方面的优化

- 智能死循环检测：发现循环输出主动中断
- 缓存命中率优化：提升 Context Caching 命中率
- 智能上下文压缩：无损压缩历史对话
- Agent 任务分层架构：高 Token 消耗任务交由子 Agent 独立处理
- 模型定向优化：针对不同模型定制系统提示词

## 知识点

- **适时新开对话**：每个对话专注于一个独立任务，避免上下文污染导致 AI "失忆"和 Token 浪费
- **精准限定范围**：明确指定要修改的文件和代码范围，减少噪声输入，让 AI 聚焦关键信息
- **优化输入内容**：使用结构化 Prompt、明确角色和输出格式，利用 TRAE 的"优化输入内容"功能提高沟通效率
- **批量处理**：将多个相关子任务打包成复合指令，减少"一问一答"的碎片化交互，降低固定开销
- **主动引导输出**：使用辅助指令（如"直接给出代码，不要解释"）控制生成内容，指定输出格式
- **先计划再行动**：用 /plan 和 /spec 模式驾驭复杂任务，确认后再执行，避免大规模返工
- **上下文压缩**：在任务阶段切换或 AI 响应质量下降时压缩上下文，为对话"减负"
- **固化长期知识**：将个人编码习惯、团队规范等固化到 Rules/Skills/Memory 中，避免重复声明
- **配置 Ignore 文件**：排除 dist/、build/ 等噪声文件，防止误操作将大文件带入上下文导致 Token 飙升
- **根据任务选择模型**：简单任务用性价比模型，复杂任务用高性能模型，避免在同一任务中频繁切换模型
