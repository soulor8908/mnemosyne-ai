# 理解 Token 和上下文窗口

作者：咸鱼 TRAE 开发者用户 / 小菠 TRAE 用户运营

**摘要：** TRAE 国际版于 02 月 24 日正式上线新版计费方式后，我们收到的高频反馈之一是：为什么 Token 消耗得这么快？一段看似简单的对话，却对应了不低的 Dollar Usage，让不少同学在使用时难免有所顾虑。在既定用量套餐下，如何更高效、更精细地使用 AI，将预算真正用在「刀刃」上？本文将从两个基础而关键的概念：「Token」和「上下文窗口」切入，帮助大家先理解用量消耗的原理，理解了 Token 消耗的原理后，我们就能对症下药，系统性地节省开销。

### AI 如何"思考"和"表达"

AI 工作的核心原理：**根据你已经给出的内容，预测下一个最可能出现的字词。**

1. **理解输入**：LLM 理解你的意图
2. **预测下一个词**：基于输入，计算每个词出现的概率，选择概率最高的
3. **更新 context，继续预测**：每生成一个新词，都重新"看"一遍之前所有内容
4. **重复直到完成**

这个过程叫做**自回归生成（Autoregressive Generation）**。每输出一个新词，都要重新处理一遍所有内容，生成的内容越长，计算量越大，速度越慢，成本越高。

### Token：AI 的处理文本的最小"计量单位"

Token 是 AI 处理文本的最小单位，也是计费的"货币"。AI 不直接阅读人类文字，而是先把文字拆成一个个 Token，再进行处理。

- 完整单词（如 `function`）= 1 Token
- 不常见单词（如 `unbelievable`）= 3 Tokens
- 汉字 = 1-2 Tokens（取决于模型）
- 标点符号 = 1 Token
- 数字 = 3-5 Tokens

每次 AI 互动包括 2 个费用：
- **输入 Token**：你发给 AI 的所有内容
- **输出 Token**：AI 回答给你的内容

输出 Token 通常比输入贵 5-8 倍，但总成本往往仍由输入主导（输入数量远大于输出）。

**中文 VS 英文：** 对于 GPT 这类主要用英文语料训练的模型，1000 个英文单词 ≈ 750 Tokens，1000 个中文字符 ≈ 1500-2000 Tokens。同样的意思，中文消耗的 Token 几乎是英文的 2 倍。

### 上下文窗口：AI 的"短期记忆"

上下文窗口就是 AI 一次能处理的最大 Token 数量（输入+输出），相当于 AI 的"工作台大小"。

上下文窗口包括：
- 系统提示（System Prompt）：定义 AI 角色和行为准则
- 工具定义（Tool Definitions）：AI 能使用的各种工具的详细说明书（占据大头）
- 记忆文件（Memory Files）：项目背景、个人偏好等
- 对话历史（Chat History）：每一轮的交流
- 自动压缩缓冲区：系统预留的"应急空间"

**上下文窗口并不是越大越好：**
1. **注意力分散**：Attention 计算量是 O(n²)，过多信息中关键信息容易被淹没
2. **计算成本**：更大的窗口意味着更高的计算成本
3. **延迟增加**：窗口越大，响应速度越慢

### Coding Agent 为什么这么费 Token？

Coding Agent 的消耗来自两个方面：

**【静态开销】携带"工具箱"太重**
- 每个工具需要一份详细的"说明书"（JSON Schema）
- 50-100 个工具的定义可能占用数万个 Token
- 不常用的工具也在默默占用上下文空间
- 解决方案：精简工具箱、优先使用轻量化工具（Skill 按需加载）

**【动态开销】执行结果中的"噪音"淹没关键信号**
- Agent 在【思考-行动-观察】循环中工作
- "信号-噪音倒置"：正常部分（噪音）占绝大多数，出错部分（信号）才包含真正需要关注的信息
- 解决方案：过滤噪音（定制测试脚本只输出失败信息）、积累经验文档、目标驱动裁剪

### 核心原则

减少 AI 的"废动作"和"废话"。你帮 AI 聚焦得越多，它为你节省的就越多，同时结果也会越好。

## 知识点

- **Token 是计费货币**：Token 是 AI 处理文本的最小单位，每次互动包括输入 Token 和输出 Token 两部分费用
- **自回归生成原理**：AI 每输出一个新词都要重新处理所有上下文，内容越长计算量越大、成本越高
- **上下文窗口机制**：AI 的"短期记忆"决定了一次能处理的最大信息量，超出后早期内容会被"挤出"
- **中文 Token 效率**：对英文语料训练的模型，中文 Token 消耗约为英文的 2 倍，国产模型已解决此问题
- **输出比输入贵的原因**：输出是逐 Token 串行生成，独占运算资源，摊到单个 Token 上的成本更高
- **Coding Agent 成本构成**：静态开销（工具定义）+ 动态开销（执行结果噪音），工具定义可能占用数万 Token
- **上下文窗口并非越大越好**：Attention 计算量 O(n²) 增长，过多信息导致注意力分散和成本飙升
- **降本核心原则**：减少 AI 的"废动作"和"废话"，精简工具箱，过滤执行结果噪音
