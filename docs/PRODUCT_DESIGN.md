# Mnemosyne · 产品设计文档

> AI 时代的云笔记产品 —— 属于你自己的、永不丢失、永不被涨价夺走的第二大脑。
>
> 本文档基于 [devpath-ai](https://github.com/soulor8908/devpath-ai) 已在生产验证的技术栈（Next.js 15 + React 19 + Dexie/IndexedDB + Cloudflare KV/Workers AI + Vercel AI SDK + ts-fsrs + Zod + 4 层质量门禁）进行产品设计。

---

## 0. 文档约定

- **设计原则来源**：乔布斯视角主导产品体验与价值观，卡帕西视角主导技术取向（详见技术设计文档）。
- **技术栈基线**：所有产品功能必须能在 devpath-ai 已验证的技术栈上落地；新增基础设施需在技术设计文档中显式标注"扩展项"。
- **术语**：L1=基础设施层 / L2=数据层 / L3=智能层 / L4=交付层，沿用 devpath-ai 的分层命名。

## 1. 产品定位

### 1.1 一句话定位
**让 AI 替你维护知识库，让你的思考永不丢失，并永远属于你自己。**

### 1.2 与现有产品的根本差异

| 维度 | Evernote / Notion / 语雀 | Obsidian / Logseq | **Mnemosyne** |
|---|---|---|---|
| 数据主权 | 厂商持有，导出有损 | 本地文件，自托管门槛高 | 本地 IndexedDB + Cloudflare KV 加密备份，一键导出 markdown |
| 维护主体 | 用户手动整理标签/链接 | 用户手动整理 | **AI 是知识库的主人，用户是读者** |
| 离线可用 | 部分支持 / 不支持 | 完全支持 | 完全支持（PWA + local-first） |
| 价格可持续性 | 已多次涨价 | 买断 / 免费 | Cloudflare 免费层兜底，架构上保证可持续 |
| AI 角色 | 补全 / 操作工作区 | 插件式 | 沉默管家：链接、提炼、修剪、复利 |
| 笔记复习 | 无 | 无 | 内置 FSRS 间隔重复，让"看过的"变成"记住的" |

### 1.3 设计价值观（乔布斯视角）

乔布斯会痛恨的当前笔记产品特征，正是 Mnemosyne 要避免的：

1. **功能堆砌** —— Notion 把数据库、看板、wiki、项目塞进一个产品，用户被自己的工作区淹没。Mnemosyne 只做笔记 + 复习 + AI 整理，不做协作表格、不做项目管理。
2. **把用户当数据搬运工** —— 让用户每周花两小时整理标签、补链接。Mnemosyne 的 AI 在用户合上笔记本后悄悄做这件事。
3. **不诚实的产品** —— 免费诱你进来，涨价时拿走你的数据当人质。Mnemosyne 把"永久免费"做成架构事实而非营销话术。
4. **AI 作为噱头** —— 把"自动补全"包装成"AI 革命"。Mnemosyne 的 AI 不替用户写，只替用户整理结构。

乔布斯会坚持的产品原则：

- **聚焦一件事**：笔记产品的本质是"让思考不丢失，并能在需要时被想起"。其他都是噪音。
- **默认离线、可选云**：永远在、永远属于你、永远不依赖某个公司的服务器心情。
- **零配置**：装上就用，不需要选模板、不需要建数据库、不需要学双链语法。
- **数据即文件**：每条笔记是一个 markdown 文件，AI 也能直接读，用户随时可以拷走。

## 2. 目标用户与痛点映射

### 2.1 目标用户画像

**核心用户**：知识工作者、研究者、终身学习者、内容创作者。特征：
- 每天产生大量碎片思考（读书笔记、会议记录、灵感、技术摘录）
- 现有笔记库已超过 500 条，开始感到"找不到、记不住、维护累"
- 对数据主权敏感，不愿把私人思考放到厂商服务器
- 已用过 2+ 款笔记产品，经历过迁移痛苦或涨价背叛

**次要用户**：备考学生、技能学习者。他们需要"笔记 + 复习"一体化，而非"笔记 + Anki"双工具。

### 2.2 痛点 → 产品机会映射

| # | 用户痛点（来自一手调研） | Mnemosyne 的回应 |
|---|---|---|
| P1 | Notion 导出有损、内部链接断裂、文件夹名混乱 | 本地 markdown 文件即真理，UI 只是视图；一键导出 zip 含所有 md + frontmatter + 附件 |
| P2 | Evernote 免费版从 10 万条砍到 50 条 | Cloudflare 免费层兜底，首页公示每用户基础设施成本 |
| P3 | 联网才能用、不翻墙访问慢 | local-first PWA，断网完全可用，联网仅用于备份与 AI |
| P4 | 笔记一多就卡、加载慢 | Dexie 索引按需加载，单笔记渲染 < 50ms |
| P5 | 印象笔记广告多、双链要收费 | 永无广告；双链由 AI 自动生成，免费 |
| P6 | "存了 3000 条笔记，AI 每次从零开始" | 内置向量索引（Workers AI bge-base-en-v1.5）+ 本地 transformers.js，AI 对话自带知识库上下文 |
| P7 | "RAG 读完就忘、只读不写、不会自我修剪" | 夜间 Agent Worker 自动链接、合并、归档提议 |
| P8 | "知识库不是资产，是负债" | FSRS 复习 + 知识地图，让存量知识持续产生复利 |
| P9 | 厂商持有密钥，员工可读 | 零信任 session 加密，MASTER_KEY 仅用户持有，服务端只见密文 |
| P10 | 笔记软件不支持批量导出 | "数据即文件"原则，导出是原生能力而非附加功能 |

## 3. 核心价值主张

### 3.1 三大产品原则

1. **你的笔记永远是你的**
   - 本地 IndexedDB 优先，markdown 文件即数据真理
   - 云端只存加密备份，密钥由用户持有
   - 30 秒内可带走全部数据离开

2. **AI 替你整理，而不是替你写**
   - 写作归用户，结构归 AI
   - AI 生成"提议"而非直接修改，用户一秒确认
   - AI 在后台沉默工作，不打扰写作心流

3. **永久免费、永久在线**
   - Cloudflare 免费层兜底基础功能
   - 永不涨价承诺写入架构（成本可公示）
   - 用户自带 API Key 模式，平台不抽成

### 3.2 价值闭环

```
捕获 → 写作 → AI 整理 → 复习激活 → 知识复利
 ↑                                    ↓
 └────── 检索时被想起 ←────────────────┘
```

- **捕获**：无感入库，碎片不丢失
- **写作**：极简编辑器，心流不被打断
- **AI 整理**：夜间 Agent 自动链接、提炼、修剪
- **复习激活**：FSRS 让"看过的"变成"记住的"
- **知识复利**：每周知识地图，新概念自动接入旧体系
- **检索时被想起**：语义检索 + 自然语言问答

## 4. 功能模块设计

### 4.1 L4 交付层 —— 用户直接感知的能力

#### 4.1.1 无感捕获（Capture）

**用户故事**：作为知识工作者，我希望在任何场景下都能 1 秒内把信息存进知识库，不用想"放哪""叫什么""怎么分类"。

**功能详情**：
- **浏览器剪藏插件**：自动提取正文、去广告、转 markdown，保留来源 URL 与发布时间
- **移动端速记**：语音转文字（Workers AI Whisper 或浏览器原生 Web Speech API）→ AI 自动生成标题与 1-3 个标签
- **微信/TG Bot 入口**：转发即入库，AI 自动归类到最相关的现有主题
- **快速笔记快捷键**：桌面端全局快捷键唤起浮层，输入即存，ESC 关闭
- **邮件转发入库**：每个用户分配专属邮箱，转发邮件正文自动转 markdown

**设计原则**：捕获时零决策。分类、标题、标签全部由 AI 事后补全，用户只负责"扔进去"。

**技术约束**：剪藏插件产物为 markdown + frontmatter，与主应用数据格式完全一致。

#### 4.1.2 极简编辑器（Write）

**用户故事**：作为写作者，我希望编辑器永远不让我分心，断网也能写，多设备编辑不冲突。

**功能详情**：
- **单栏无干扰 markdown 编辑器**：所见即所得，不提供数据库、看板、表格等"伪需求"
- **本地优先**：所有编辑先写本地 Dexie/IndexedDB，断网完全可用
- **跨设备同步**：联网时增量同步到 Cloudflare KV，冲突由时间戳 + 字段级合并解决
- **版本历史**：每次保存生成快照，可回溯任意历史版本（本地保留 30 天，云端按需）
- **全文搜索**：Dexie FTS 索引，< 50ms 返回结果
- **附件管理**：图片、PDF、音频拖拽即存，小附件走 KV，大附件走 R2（扩展项）

**设计原则**：编辑器只做编辑。所有"管理"动作（分类、链接、标签）由 AI 在后台完成，不在编辑器内打扰用户。

**与 devpath-ai 的复用**：直接复用其 Next.js 15 + Tailwind 3 + Dexie 的编辑器骨架与 IndexedDB 抽象层。

#### 4.1.3 沉默的 AI 助手（Agent）—— 差异化核心

**用户故事**：作为知识库所有者，我希望 AI 在我睡觉时替我整理笔记，第二天早上给我一份"待确认提议清单"，而不是悄悄改我的东西。

**功能详情**：

每日凌晨 Cron Worker 跑一次"夜间整理"，产出**提议**而非直接修改：

- **链接提议**：发现新笔记与旧笔记的语义关联，提议插入 `[[双链]]`，并在文末生成"相关思考"区块
- **提炼提议**：识别同一主题的多个碎片笔记，提议合并成一篇"沉淀笔记"，原文保留为引用块
- **修剪提议**：标记 6 个月未访问且与其他笔记高度重复的条目，提议归档（永不删除）
- **复利提议**：每周生成"知识地图"——本周新概念如何连接到已有体系，可视化展示
- **触发提议**：监测到笔记中提到"下周要交 XX 报告"，提议在到期前从知识库提取相关笔记组成草稿
- **复习建议**：基于 FSRS 算法，提议今天该复习哪 5-10 条笔记

**用户确认机制**：
- 所有提议进入"收件箱"，用户一秒滑动确认或忽略
- 高置信度提议（如明显重复内容）可开启"自动应用"模式，用户事后审计
- 每条提议附带"为什么"——AI 给出关联理由，让用户能学习 AI 的思考方式

**设计原则**：
- **AI 不替用户做决定**：所有修改经用户确认（乔布斯原则）
- **AI 主导维护**：用户是读者而非维护者（卡帕西 LLM Wiki 构想）
- **可解释**：每条提议都有理由，黑盒 AI 不可接受

**与 devpath-ai 的复用**：复用其 AI SDK 流式对话 + 工具调用 + 幂等键机制；Cron Worker 复用其 Workers 部署模式。

#### 4.1.4 语义检索（Recall）

**用户故事**：作为知识库所有者，我希望问 AI 一个问题，它能从我自己的笔记里找答案，并标注引用来源，而不是从公开互联网编一个。

**功能详情**：
- **自然语言问答**："我去年读过的关于系统设计的那本书里讲了什么？"
- **混合检索**：Dexie 本地 FTS（关键词）+ Workers AI bge-base-en-v1.5 嵌入（语义），双路召回后用 LLM 重排
- **带引用的回答**：每个回答附带 3-5 条笔记引用，可一键跳转原文
- **隐私保护**：嵌入向量本地生成（@xenova/transformers）+ 云端 Workers AI 双模式；敏感笔记可标记"仅本地"
- **跨笔记综合**：AI 可综合多篇笔记回答"对比""演化""关联"类问题

**设计原则**：检索是"被想起"，不是"被搜索"。用户应该惊讶于 AI 居然记得自己写过这个。

**与 devpath-ai 的复用**：直接复用其 Workers AI binding（bge-base-en-v1.5）+ @xenova/transformers 本地推理 + AI SDK 工具调用架构。

#### 4.1.5 FSRS 复习（Review）

**用户故事**：作为学习者，我希望笔记能像 Anki 卡片一样按遗忘曲线复习，但不用我手动做卡片。

**功能详情**：
- **自动生成复习卡**：AI 从每条"沉淀笔记"中提取 2-3 个核心知识点，生成正面问题 / 反面答案的复习卡
- **FSRS 调度**：基于 ts-fsrs 4.5 的间隔重复算法，3 种参数预设（conservative 0.95 / standard 0.9 / aggressive 0.8）
- **每日复习队列**：首页展示今日待复习卡片数，预计耗时
- **热力图可视化**：年度复习热力图，Streak 连续天数
- **复习反馈循环**：复习时的"记不住"会反馈给 AI，提示其重新组织该笔记或生成更多关联

**设计原则**：笔记即卡片原料。不强迫用户维护两套系统（笔记 + Anki）。

**与 devpath-ai 的复用**：直接复用其 ts-fsrs 4.5 集成、3 种预设、热力图可视化（react-activity-calendar）。

#### 4.1.6 数据主权（Ownership）

**用户故事**：作为长期用户，我希望随时能带走全部数据，不被任何厂商绑架。

**功能详情**：
- **一键导出**：所有 markdown + frontmatter + 附件打包成 zip，保留目录结构与双链
- **自托管**：开源版本可部署到任意 Cloudflare 账户或本地 Node 服务
- **迁移工具**：从 Evernote(ENEX)、Notion(export zip)、Obsidian(vault) 一键导入
- **数据删除权**：一键清除本地 + 云端 + 向量索引中的所有数据，符合 GDPR
- **数据可读性**：所有数据都是 markdown + JSON 元数据，10 年后仍可读

**设计原则**：用户的"离开权"是产品最神圣的承诺。导出功能必须在首页可达，而非藏在设置深处。

### 4.2 L3 智能层 —— AI 能力编排

#### 4.2.1 分层 AI 架构

| 层级 | 运行位置 | 模型 | 任务 | 成本 |
|---|---|---|---|---|
| L1 实时层 | 浏览器内 | @xenova/transformers 小模型 | 补全、纠错、标题生成 | 免费 |
| L2 同步层 | Cloudflare Workers AI | bge-base-en-v1.5 | 嵌入生成、摘要、标签 | 免费额度 |
| L3 深度层 | 用户自带 Key（DeepSeek/GLM/OpenAI） | 大模型 | 跨笔记综合、长文写作、Agent 任务 | 用户承担 |
| L4 后台层 | Cron Worker（每日） | 大模型（L3 路由） | 知识库健康检查、合并、链接、知识地图 | 用户承担/平台 Trial |

**与 devpath-ai 的复用**：完全复用其"用户自带 Key 走零信任 session 加密 + 服务端 Trial 模式按场景配额"的双模式架构，以及多 provider 路由（DeepSeek / GLM / OpenAI 兼容）。

#### 4.2.2 Agent 工具集

夜间 Agent 通过工具调用执行任务，所有工具遵循 devpath-ai 的幂等键机制：

| 工具 | 功能 | 幂等策略 |
|---|---|---|
| `create_proposal` | 生成一条整理提议 | 基于 (noteId, action, targetHash) 去重 |
| `link_notes` | 在两篇笔记间插入双链 | 基于 (srcId, dstId) 去重 |
| `merge_notes` | 提议合并多篇笔记为沉淀笔记 | 基于 (noteIds 排序哈希) 去重 |
| `archive_note` | 提议归档低价值笔记 | 基于 noteId 去重 |
| `generate_review_card` | 从笔记生成复习卡 | 基于 (noteId, questionHash) 去重 |
| `update_knowledge_map` | 更新知识地图可视化 | 基于 weekKey 去重 |
| `schedule_reminder` | 基于笔记内容创建未来提醒 | 基于 (noteId, triggerDate) 去重 |

#### 4.2.3 模型路由策略

不同任务路由到不同模型（参考 Notion 3.0 的多模型思路）：

- **创意写作 / 长文生成** → 用户偏好的大模型（默认 GLM-4.6 或 DeepSeek）
- **分析 / 跨笔记综合** → Claude / GLM-4.6
- **摘要 / 标签 / 标题** → Workers AI 或小模型（成本优先）
- **嵌入生成** → Workers AI bge-base-en-v1.5（免费）或本地 transformers.js
- **多模态（图片 OCR）** → Gemini / GLM-4V

用户可在设置中为每类任务指定偏好模型。

### 4.3 L2 数据层 —— 数据模型与同步

详见技术设计文档第 4 节。产品层面的关键承诺：

- **本地优先**：所有数据先写 IndexedDB，断网完全可用
- **加密备份**：同步到 Cloudflare KV 的内容均为密文，MASTER_KEY 仅用户持有
- **增量同步**：只传 delta，单次同步 < 10KB
- **多设备**：通过 KV 作为中转，支持 3+ 设备同步

### 4.4 L1 基础设施层 —— 部署与成本

详见技术设计文档第 6 节。产品层面的关键承诺：

- **永久免费层**：Cloudflare 免费层覆盖 1 个用户的基础使用
- **成本透明**：首页实时显示"本月每用户基础设施成本"
- **自托管可行**：开源 + 一键部署到任意 Cloudflare 账户

## 5. 用户体验设计

### 5.1 信息架构

```
Mnemosyne
├── 今日 (Today)
│   ├── 待复习卡片 (FSRS 队列)
│   ├── AI 提议收件箱
│   └── 快速捕获入口
├── 笔记 (Notes)
│   ├── 全部笔记 (按时间/标签/主题)
│   ├── 文件夹 (用户自建)
│   └── 双链图谱 (可视化)
├── 知识地图 (Map)
│   ├── 本周知识复利
│   ├── 概念关联图
│   └── 历史地图回溯
├── 检索 (Recall)
│   ├── 自然语言问答
│   └── 最近检索
└── 设置 (Settings)
    ├── 数据导出/导入
    ├── AI 模型配置 (自带 Key)
    ├── 同步状态
    └── 隐私与加密
```

### 5.2 关键交互流

#### 5.2.1 首次使用流（零配置原则）

1. 打开 https://mnemosyne.pages.dev
2. PWA 引导安装到桌面（可选）
3. 直接进入编辑器，输入第一条笔记
4. 无需注册、无需选模板、无需建数据库
5. 首次联网时引导：是否启用云备份？是否填入 AI API Key？（均可跳过）

**对比 Notion**：Notion 首次进入要选模板、建 workspace、邀团队成员。Mnemosyne 首次进入 = 一个空白笔记 + 光标。

#### 5.2.2 写作心流保护

- 编辑器全屏模式：隐藏所有侧边栏、AI 提议、复习提醒
- 写作时 AI 仅做静默补全（L1 本地模型），不弹提议
- 提议只在用户主动打开"收件箱"或退出编辑器时呈现
- 复习提醒每日最多 3 次，可静音

#### 5.2.3 提议确认流

```
[收件箱] AI 提议 5 条
  ├─ 链接提议：「React 性能优化」 ↔ 「虚拟列表原理」 (相似度 0.87)
  │   [查看理由] [接受] [忽略] [永远忽略此类]
  ├─ 合并提议：3 篇「系统设计面试」碎片 → 1 篇沉淀笔记
  │   [预览合并结果] [接受] [忽略]
  ├─ 归档提议：「2023 年读书清单」6 个月未访问
  │   [保留] [归档] [永久保留（标记）]
  ├─ 复习建议：今日 7 张卡，预计 5 分钟
  │   [开始复习]
  └─ 触发提议：你 3 天后要交"年终总结"，已找到 5 篇相关笔记
      [生成草稿] [忽略]
```

每条提议的"为什么"展开后显示 AI 的推理链：
> "你 3 天前在《React 性能优化》笔记中写道'虚拟列表是大数据量渲染的核心方案'，而《虚拟列表原理》详细剖析了实现机制。建议建立双链，未来检索任一篇都能联动。"

### 5.3 视觉设计原则

- **极简**：单色主调 + 一个强调色，无渐变、无阴影堆叠
- **专注**：默认编辑区占视口 70%+，其他元素折叠
- **可读**：正文 16px / 1.7 行高，代码 JetBrains Mono
- **不打扰**：所有通知可静音，所有动画可关闭（无障碍）
- **诚实**：成本、AI 调用次数、同步状态在设置中完全透明

### 5.4 移动端适配

- PWA 优先，不强制做原生 App
- 移动端首屏 = 速记入口（语音/文字）+ 今日复习卡
- 列表页支持左滑归档、右滑收藏
- 离线 PWA 缓存所有已读笔记

## 6. 商业模式

### 6.1 三层定价

| 层级 | 价格 | 包含 |
|---|---|---|
| **Free** | $0 永久 | 本地无限笔记 + Cloudflare 免费层云备份（10GB）+ Workers AI 免费额度 + 本地 AI |
| **Pro** | $5/月 | 解锁：更多 Workers AI 调用额度、更长向量索引、Cron Agent 每日跑、多设备实时协同、版本历史 1 年 |
| **BYOK** | $0 平台费 | 用户填自带 OpenAI/Anthropic/DeepSeek/GLM Key，平台只收基础设施成本（按量透明） |

### 6.2 永不涨价的架构保证

devpath-ai 已验证 Cloudflare 免费层可承载一个生产级 AI 应用。Mnemosyne 把这一点变成核心承诺：

- Free 层功能 = Cloudflare 免费层能覆盖的功能
- 若 Cloudflare 调整免费额度，Free 层功能相应调整，但**永不向已注册用户收费**
- 首页公示"本月每用户基础设施成本"，证明 Free 层可持续

### 6.3 与 Evernote/Notion 商业模式对比

| 维度 | Evernote/Notion | Mnemosyne |
|---|---|---|
| 收入来源 | 订阅费 + 企业版 + 数据锁定税 | Pro 订阅 + BYOK 基础设施差价 |
| 涨价动机 | 服务器成本上升 + 增长压力 | 无涨价压力（免费层兜底） |
| 用户离开成本 | 极高（数据锁定） | 极低（一键导出） |
| 长期可持续性 | 依赖持续涨价 | 依赖用户主动升级 Pro（AI 调用量驱动） |

## 8. 成功指标

### 8.1 北极星指标
**"AI 提议接受率"** —— 用户接受 AI 整理提议的比例。
- 含义：AI 真的在帮用户，而非打扰用户
- 目标：> 60%（行业 AI 提议接受率平均 30%）

### 8.2 关键体验指标

| 指标 | 目标 | 含义 |
|---|---|---|
| 编辑器首屏加载 | < 1.5s | local-first 的体感 |
| 断网可用率 | 100% | 核心承诺 |
| 单次同步耗时 | < 500ms | 多设备体验 |
| AI 问答首 token | < 800ms | 检索体验 |
| 7 日用户主动检索次数 | > 5 次 | 知识库被"用起来" |
| FSRS 复习完成率 | > 70% | 复习闭环成立 |
| 数据导出耗时 | < 30s | 离开权承诺 |
| 30 日留存 | > 40% | 产品价值验证 |

### 8.3 反指标（警惕的信号）

- **用户主动整理标签的时间增加** → 说明 AI 没承担维护责任
- **AI 提议忽略率 > 70%** → 说明 AI 在打扰而非帮忙
- **导出功能使用率 > 20%/月** → 说明用户在准备离开（需反思产品价值）
- **免费用户 Workers AI 调用逼近额度上限** → 需优化调用策略或调整额度

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Cloudflare 调整免费层额度 | Free 层不可持续 | 架构保证"已注册用户永不收费"；预留自托管逃生路径 |
| 大模型 API 涨价 | BYOK 用户成本上升 | 多 provider 路由，永远有备选；本地 transformers.js 兜底基础能力 |
| AI 提议质量低 | 用户信任崩塌 | 提议必须附"为什么"；低置信度不提议；用户反馈闭环优化 prompt |
| 数据丢失 | 信任崩塌 | 本地 IndexedDB + 云端 KV + 可选 R2 三副本；版本历史可回溯 |
| 隐私泄露 | 法律与信任风险 | 零信任 session 加密；MASTER_KEY 仅用户持有；服务端只见密文 |
| 功能蔓延 | 产品变形为 Notion 2.0 | 严格守住"笔记+复习+AI整理"边界；拒绝加协作/看板/数据库 |
